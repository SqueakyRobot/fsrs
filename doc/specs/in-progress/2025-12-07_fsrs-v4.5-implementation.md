# FSRS v4.5 Implementation Specification

**Status**: 🚧 In Progress
**Created**: 2025-12-07
**Target Version**: 1.0.0
**Algorithm Version**: FSRS v4.5 (with v6 compatibility)

## Executive Summary

Implementation of the Free Spaced Repetition Scheduler (FSRS) v4.5 algorithm as a pure TypeScript library. This library provides a trainable, evidence-based spaced repetition scheduling system based on the DSR (Difficulty, Stability, Retrievability) model of memory.

The implementation targets FSRS v4.5 (17 parameters) as the primary algorithm, with data structures designed to accept v6 (21 parameters) for advanced users who have optimized parameters. This approach provides:
- **Proven stability**: v4.5 captures 98% of v6's improvement with 19% fewer parameters
- **Minimal complexity**: No same-day review logic required
- **Deterministic defaults**: Stable behavior without requiring parameter optimization
- **Future-proof**: Can accept v6 parameters when users provide them

## Theoretical Foundation

### The DSR Model

FSRS separates memory modeling into three distinct variables:

1. **Difficulty (D)**: Inherent complexity of the item (1.0 = easiest, 10.0 = hardest)
   - Influences how quickly stability increases after successful reviews
   - Updates based on user feedback with mean reversion to prevent extremes

2. **Stability (S)**: Storage strength of the memory trace
   - Defined as the time interval (days) for retrievability to decay from 100% to 90%
   - At 90% retention, optimal interval equals stability (I = S)

3. **Retrievability (R)**: Instantaneous probability of successful recall
   - Value between 0 and 1
   - Decays over time following a power-law distribution (not exponential)

### Key Advantage Over SM-2

FSRS v4.5 demonstrates ~81% improvement in RMSE over SM-2 through:
- Power-law forgetting curve (vs. exponential)
- Trainable parameters optimized on real user data
- Decoupled difficulty and stability modeling
- Simpler, more stable algorithm with proven defaults

## Mathematical Specifications

### Core Parameters

**V4.5 Parameter Set** (17 weights: w₀ through w₁₆):

| Index | Name | Description | Default |
|-------|------|-------------|---------|
| w₀-w₃ | Initial Stability | First review stability for Again/Hard/Good/Easy | 0.4/0.6/2.4/5.8 |
| w₄-w₅ | Initial Difficulty | Difficulty calculation for new cards | 4.93/0.94 |
| w₆ | Difficulty Update Factor | Magnitude of difficulty change | 0.86 |
| w₇ | Difficulty Mean Reversion | Rate of return to baseline | 0.01 |
| w₈ | Stability Update Base | Base factor for stability increase | 1.49 |
| w₉ | Stability Update Exp (S) | Current stability exponent | 0.14 |
| w₁₀ | Stability Update Exp (R) | Current retrievability exponent | 0.94 |
| w₁₁-w₁₄ | Stability After Lapse | Lapse recovery parameters | 2.18/0.05/0.34/1.26 |
| w₁₅ | Hard Penalty | Stability multiplier for "Hard" | 0.29 |
| w₁₆ | Easy Bonus | Stability multiplier for "Easy" | 2.61 |

**Optional V6 Extensions** (if 21 weights provided):
| w₁₇-w₁₉ | Same-Day Review | Short-term memory parameters (optional) | - |
| w₂₀ | Decay Exponent | Dynamic curve fitting (optional) | -0.5 default |

### Forgetting Curve

**Primary Formula** (v4.5 - fixed exponent):
```
R(t, S) = (1 + (19/81) · (t/S))^(-0.5)

where:
  R = Retrievability (probability of recall)
  t = Time elapsed since last review (days)
  S = Stability (days to 90% retention)
  F = 19/81 ≈ 0.2345679 (scaling factor)
```

**Optional V6 Extension** (if w₂₀ provided):
```
R(t, S) = (1 + F · (t/S))^(w₂₀ / C)
where:
  C = -0.5 (decay constant)
  w₂₀ = user-specific curve exponent (defaults to -0.5)
```

### Interval Calculation

Invert retrievability formula to solve for time when R = R_req:

```
I(S, R_req) = (S/F) · (R_req^(-2) - 1)
            = S · (81/19) · (R_req^(-2) - 1)
```

For R_req = 0.9, this simplifies to I ≈ S.

### State Updates

#### Initial Review (New Card)

**Stability**:
```
S₀(G) = w_{G-1}
```

**Difficulty**:
```
D₀(G) = w₄ - e^(w₅ · (G-1)) + 1
```
Clamped to [1, 10].

#### Successful Review (Grade ≥ 2)

**Difficulty Update**:
```
D_next = D_prev - w₆ · (G - 3)
D_new = w₇ · D₀(3) + (1 - w₇) · D_next
```
Clamped to [1, 10].

**Stability Update**:
```
GrowthFactor = e^(w₈) · (11 - D_new) · S_prev^(-w₉) · (e^(w₁₀(1-R)) - 1) · h · b

where:
  h = w₁₅ if G=2 (Hard penalty), else 1
  b = w₁₆ if G=4 (Easy bonus), else 1

S_new = S_prev · (1 + GrowthFactor)
```

#### Lapse (Grade = 1)

**Stability Update**:
```
S_new = w₁₁ · D_new^(-w₁₂) · ((S_prev + 1)^(w₁₃) - 1) · e^(w₁₄(1-R))
S_final = min(S_prev, S_new)
```

### V6 Extensions (Optional)

The library accepts v6 parameter sets (21 weights) for advanced users who have run the FSRS optimizer on their review history. When 21 weights are provided:

**Dynamic Forgetting Curve** (w₂₀):
- Allows personalized curve shape instead of fixed -0.5 exponent
- Only beneficial when optimized on user-specific data
- Defaults to v4.5 behavior if not provided

**Same-Day Reviews** (w₁₇-w₁₉):
- Short-term memory adjustments for multiple reviews within 24 hours
- Requires timestamp precision (not just dates)
- **Deferred to post-v1.0** due to complexity and minimal benefit without optimization

## API Design

### Type Definitions

```typescript
/**
 * User feedback ratings
 */
export type Rating = 1 | 2 | 3 | 4; // Again | Hard | Good | Easy

/**
 * Card learning states
 */
export type State = 0 | 1 | 2 | 3; // New | Learning | Review | Relearning

/**
 * Core memory state
 */
export interface Card {
  due: Date;              // Next review timestamp
  stability: number;      // Days to 90% retention
  difficulty: number;     // Complexity (1-10)
  elapsed_days: number;   // Days since last review
  scheduled_days: number; // Assigned interval
  reps: number;           // Total review count
  lapses: number;         // Failure count
  state: State;           // Current phase
  last_review: Date;      // Previous review timestamp
}

/**
 * Review history record
 */
export interface ReviewLog {
  rating: Rating;
  state: State;
  due: Date;
  stability: number;
  difficulty: number;
  elapsed_days: number;
  last_elapsed_days: number;
  scheduled_days: number;
  review: Date;
}

/**
 * Algorithm configuration
 */
export interface FSRSParameters {
  request_retention: number;  // Target retention (0.7-0.97, default 0.9)
  maximum_interval: number;   // Interval cap (default 36500 days)
  w: number[];                // Weight vector (17 for v4.5, 21 for v6)
  enable_fuzz: boolean;       // Random interval jitter
  enable_short_term?: boolean; // V6 same-day logic
}
```

### Main Class

```typescript
export class FSRS {
  private params: FSRSParameters;

  constructor(params?: Partial<FSRSParameters>);

  /**
   * Calculate card state for all possible ratings
   * @returns Map of Rating -> { log, card }
   */
  repeat(card: Card, now: Date): Record<Rating, { log: ReviewLog; card: Card }>;

  /**
   * Calculate current retrievability
   * Useful for UI display of retention percentage
   */
  getRetrievability(card: Card, now: Date): number;

  /**
   * Create a new empty card
   */
  createEmptyCard(now?: Date): Card;

  /**
   * Get next interval for a given rating (preview mode)
   */
  getNextInterval(card: Card, rating: Rating, now?: Date): number;
}
```

### Immutability Principle

All methods return new objects; input objects are never mutated. This ensures:
- Predictable behavior in Redux/Zustand state management
- Safe concurrent usage
- Easy undo/redo implementation

## Why V4.5 as Primary?

### The Case for V4.5

**Strategic Advantages**:
1. **98% of v6's benefit**: v4.5 achieves ~81% RMSE improvement vs SM-2; v6 adds only ~3% more
2. **No optimization required**: Proven defaults work well for generic users
3. **Simpler implementation**: No same-day review complexity
4. **Stable and proven**: Widely deployed, deterministic behavior
5. **Minimal footprint**: 19% fewer parameters than v6

**V6 Limitations Without Optimizer**:
- v6 benefits only realized when parameters are trained on user-specific data
- Using v6 defaults on generic users provides negligible improvement over v4.5
- Adds complexity without commensurate value for "minimal" implementation

### V6 Support Strategy

**Primary**: Ship with v4.5 (17 weights) as the default, optimized algorithm.

**Optional**: Accept v6 parameter sets (21 weights) for power users who have:
- Run the Python FSRS optimizer on their review history
- Generated personalized w₀-w₂₀ values
- Need the marginal 2-3% accuracy improvement

**Implementation**: Library detects weight array length and uses v6 formulas only when appropriate parameters are provided.
